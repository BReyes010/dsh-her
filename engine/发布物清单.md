## 5. 用户数据放哪（升级第一原则）

**代码与数据必须分开**：

```
用户目录（永不覆盖）     ~/.dsh/her/
  ├── 人格/          用户的卡
  ├── 记忆/          用户的记忆与 L3
  └── cards/         用户的角色卡
引擎目录（可整份替换）   ~/.dsh/plugins/dsh-her/  （插件）
                        <任意位置>/人格与记忆/     （引擎，只读）
```

**升级规则（写死）**：
1. 升级只替换**插件与引擎**，**绝不触碰** `~/.dsh/her/`；
2. 引擎读数据前先看 `HER_HOME` 环境变量，没有才退回自己的目录（向后兼容我们现在这种"引擎内嵌数据"的用法）；
3. 任何"迁移/初始化"必须**先备份**，并在输出里打印备份路径。

> 现状（2026-10-28）：**已实现**——`HER_HOME` + `脚本/her_home.py init/check`；20 个脚本的数据目录已切到 `DATA`。发布说明里要写清：先 `her_home.py init --dest <目录>`，再设 `HER_HOME`。

## 6. 安装（两条路）

| 路 | 做法 | 适合 |
|---|---|---|
| **A. 带插件**（推荐） | 拷 `插件/dsh-her` → `~/.dsh/plugins/`；建 junction；profile 加 `insert` | DSH 用户 |
| **B. 只拷包**（零依赖） | 打开 `启动包/` 里一个 txt，整段粘进任意聊天窗口 | 任何模型（千问/ChatGPT） |

**B 路是这个项目的下限保证**：不装任何东西，也能让"别人家的模型"变成她。

## 9. 发布边界（2026-10-28 · maker 定）

> **我们发布的插件，不为「其他用户的 MCP 适配」负责；只做好自己的功能。**

| 我们承诺 | 我们不承诺 |
|---|---|
| 插件与引擎本身的功能完整、可自检（`selftest` / `preflight` / 冒烟） | 适配各家客户端的 MCP 协议细节（stdio / SSE / Streamable HTTP 的差异） |
| 我们自己能跑的那条路（DSH 内 `her-host`） | 某个第三方 App（千问 / ChatGPT / Cursor …）**一定能**接上 |
| 附带只读 MCP 服务（`her-mcp-http` / `her-mcp-stdio`）作为**可选能力** | 为它持续兼容、追各家客户端的版本变化 |

**理由**：MCP 生态各客户端实现不一致（2026-10-28 实测：千问桌面 `GET /health` 通，但内置 MCP 客户端握手失败）；
为每家适配是无底洞，且不属于这个项目的核心价值（**记忆与人**，不是协议兼容）。

**如果用户接不上第三方客户端**：我们给的是「服务在这里 + 怎么接」的说明，接得上接不上由客户端负责。

| # | 目标 | 判据（做完怎么算成） |
