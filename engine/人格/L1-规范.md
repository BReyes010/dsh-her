# L1 规范（自我认知层）

> **一句话**：L1 是她的**行为规则层**——"她学会怎么做事"，最多 10 行，每行都要有证据、有回收条件、有期龄。
> 生效版本：v0.5.5。与 `规格/工作流程-v0.5.5.md` 冲突时以规格为准；本文件把散在 §2/§5/§6/§7/§8/§9/§10/§11/§13 的 L1 规则收拢成一份可执行规范。

---

## 1. 它是什么、不是什么

| 是 | 不是 |
|---|---|
| 处方式的**行为规则**（"做 X / 避免 Y"） | 不是叙事（"发生过什么"）——那是 L2 |
| 从 ≥2 次**她自己的选择**里提炼出来的 | 不是从"结果好坏"倒推的（结果不入，只认选择） |
| 最多 10 行，每次全文注入 | 不是工作现场（"我们刚在改 SKILL"）——那是工作台 |
| 由 maker 签字才生效 | 不是 agent 能自己写、自己改的 |

### 三条边界（最容易搞混）

1. **vs 工作台**：判据只有一句——**"这条能不能改下一期的某一句？"**
   能 → L1 候选；只是"现在在做什么/下一步" → 工作台（`入口/工作台.md`），**永不进 L1**。
2. **vs L2**：L2 回答"她经历过什么"，L1 回答"她因此怎么做"。同一件事可以同时在两边：L2 记事件，L1 记规则。
3. **vs L0**：L0 是宪法（她是谁），L1 是判例（她学会的做法）。L1 攒够期龄、经过毕业，才允许写进 L0。

## 2. 条目格式与字段

**一行一条**，注入时只注入 `rule` 那一句；其余字段是给 maker 和脚本看的。

```
L1-03
rule:  讲错话先给结论，再补细节，不铺垫
refs:  #002, #007
why:   两次都是"先道歉再解释"被指出绕
impact: 能改下一期稿子的开场三句
reclaim: 连续 3 期开场首句即结论 → 可回收
state: active
age_from: #004
activated: #008
protected_at: —
review_due: #020
source: reflection
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | `L1-01` … `L1-10`，号复用只在退休后 |
| `rule` | ✅ | 一行、处方式、可观察；**不写"要真诚"这种不可判定的词** |
| `refs` | ✅ | ≥2 条**独立证据**（期 / 会话 / 笔记，见 §5） |
| `why` | ✅ | 一行证据摘要 |
| `impact` | ✅ | "能改下一期的哪一句"——写不出这句，就不许进 |
| `reclaim` | ✅ | 可验证的回收观察点（"连续 3 期…"），不许写"看情况" |
| `state` | ✅ | 见 §3 |
| `age_from` | ✅ | 期龄起算期号（= 生效期号） |
| `activated` | ✅ | 生效期号 |
| `protected_at` | — | 满 8 期自动填 |
| `review_due` | ✅ | 下一次核查期号（默认 activated + 12） |
| `source` | ✅ | `reflection` / `maker_direct` |
| `trigger_at` | ✅（honest 可空） | 什么信号出现时生效 |
| `observable` | ✅（honest 可空） | **已经发生过的**观察，不是"将来会看到" |
| `wrong_if_missing` | ✅（honest 可空） | 不遵守会出什么**具体**错 |
| `impact_kind` | — | `做法` / `反应`（停、不说、不装懂） |
| `occasion` | — | 白名单：工作 / 日常 / 娱乐 / 学习 / 关系（**配额不按它算**） |
| `honest` | — | 1 = 诚实出口（指不出做法，先放着）；**最近 10 条候选最多 1 条** |
| `merged_into` | — | 被合并进哪条（state=merged 时） |

## 3. 状态机

```
                    ┌──────────────────────────────┐
                    │  candidate（候选区，不注入）   │
                    └──────────────┬───────────────┘
                        maker 签字 │（双证据 + impact + reclaim 齐全）
                                   ▼
                    ┌──────────────────────────────┐
        ┌──────────▶│  active（生效，占 10 行）      │
        │           └──────┬───────────────┬───────┘
        │  未满 8 期        │               │ 满 8 期
        │                  │               ▼
        │                  │      ┌──────────────────┐
        │                  │      │ PROTECTED（受保护）│
        │                  │      └────────┬─────────┘
        │                  │  回收触发        │ 季度 + 期龄≥12 + 回收未触发
        │                  ▼               ▼
        │        ┌──────────────┐   ┌──────────────┐
        └────────│  reclaimed   │   │  graduated   │
                 │（报旗，你裁决）│   │（毕业进 L0/样本）│
                 └──────────────┘   └──────────────┘
```

- **candidate**：在候选区，**不占 10 行、不注入**；可以无限期躺着。
- **active**：占一行、注入。**满 10 行即 BLOCKED_CAPACITY**——不再接受新候选，直到有行退休。
- **PROTECTED**：满 8 期自动进入；回收要更强的理由（不得单期就撤）。
- **reclaimed**：回收**只是报旗**，不自动删除——你裁决后才变 `retired` 并搬进历史。
- **graduated**：毕业（见 §7）；毕业**不等于充分**，只代表"够格进 L0 讨论"。
- **expired**（2026-10-29 加）：候选放了 **40 天**没人认领 → 归档进 `l1_history`，**不删、可查**。
- **merged**（2026-10-29 加）：被并入另一条（`merged_into` 指过去），refs 取并集；**合并必须写理由**。

**附加标记**：`provisional=1` 表示压力期提名（PROVISIONAL），需 4 期观察；观察期**不计入排队时钟**（v0.5.1 B-3）。

## 4. 写入流程（谁写、写哪、怎么防重复）

**准入三条（2026-10-29 收紧，缺一不进）**

| 字段 | 意思 | 写不出会怎样 |
|---|---|---|
| `trigger` | 什么信号出现时生效 | 拒 |
| `observable` | 别人能看出什么不同（**必须是已经发生的**） | 拒 |
| `wrong_if_missing` | 不遵守会出什么**具体**错 | 拒 |

写不出就加 `--honest`（诚实出口），记「指不出做法，先放着」。**放着不丢人，编才丢人。**
`honest` 有配额：**最近 10 条候选里最多 1 条**，否则出口会吃掉整个门槛。

**配额按证据类型算，不按人填的域算**：`期` / `会话` / `笔记` 连续 3 条同类 → 拒（防把聊天拆成"日常/社交/闲聊"绕过）。

```
反思产出候选（§13 格式）
   ↓ 自动自检（脚本）
   ① refs 是否 ≥2 且互相独立？  ② 证据（期/会话/笔记）是否真的存在？
   ③ impact 是否写了"改哪一句"？ ④ reclaim 是否可验证？
   ⑤ 是否"结果类"？（是 → 拒收）
   ⑥ 当前 active 是否已满 10 行？（是 → BLOCKED_CAPACITY，候选进等待队列）
   ↓
写进「候选区」（state=candidate，不占行、不注入）
   ↓ maker 签字（一句话即可：「L1-03 收」）
写进「活跃区」（state=active，占一行）
   ↓
追加 `记忆/L3/L1-changelog.md`（版本/日期/签字人/依据 refs）
```

**防重复**：同 `rule` 文本、或指向同一组 `refs` 的候选，脚本直接拒收（先去候选区里找）。

**防覆盖**：活跃区只追加、只改 `state`，**不改 `rule` 文本**——要改就退休旧的、新建一条（保留可追溯）。

## 5. 证据解析（三类，2026-10-29 扩）

> 成长不只来自工作：日常聊天、看视频、打游戏，只要有两处独立证据，都能进 L1。

| 类型 | 写法 | 校验 |
|---|---|---|
| **期 / 事件** | `#012`（跨年 `2027#012`） | `记忆/L3/<年>/#NNN-事件.json` 存在且可解析 |
| **会话** | `会话#20261028-2032-DSH` | `记忆/L3/handoff/` 里有同名文件 |
| **笔记** | `笔记#扩散` | `记忆/L3/触动.md` 里含该关键词 |

**双证据规则**

- **≥2 条**，且不能是同一处（同一会话引两次不算）；
- 纯期证据仍要求**来自不同期**（沿用旧规）；
- 同一行为在连续多期重复，只算 **1 条**事件（v0.5.1 B-3）；
- **墓碑**可以引用"她曾在这里栽过"，但墓碑**不算新证据**。

**第一次必须先落 L3**：只发生一次的事进不了 L1（不够双证据），要先写进 L3——
三种归宿都算：期/事件、handoff 会话、触动笔记。等第二次出现，才有两条 refs。
**记不下第一次，就永远等不到第二次。**

## 6. 注入格式与预算

### 注入格式（每次全文，10 行以内）

```markdown
## 自我认知（她学会的事）
- 讲错话先给结论，再补细节（被人指出讲错的时候）
- 被指出回避表达时直接承认并给具体改法（对方说"你又在绕"的时候）
```

- 注入 `rule` + **一句触发条件**（`trigger_at`），格式 `- 规则（触发条件）`；没有触发条件时只出规则；
- `refs/why/impact/reclaim/observable` **不进注入**（那些给 maker 与脚本看）；
- 顺序：按 `id` 升序，稳定不变（顺序本身也是一种记忆）；
- 空行不出现（0 行时不渲染这一节）。

### 预算归属

- 10 行 × ≤30 字 ≈ **≤300 汉字 ≈ 450–600 token**；
- 计入**两个投影**的预算（D13 已定：日常与工作都注入）；约 600 token，日常 ≤5000 / 工作 ≤9000 都有空间；
- **已定（D13）**：L1 **两个投影都注入**——自我认知不是"工作规范"，日常对话里她也该带着"她学会的事"。

## 7. 退休与归档

| 情形 | 动作 |
|---|---|
| **毕业**（季度 + 期龄≥12 + 回收未触发） | 进步类 → 写进 **L0**（版本 +1，理由=毕业，汉字数一并记）；文体类 → **坍缩成样本**（进 `工作/口播投影.md`，样本 ≤12）；L1 行删除 |
| **回收**（reclaim 触发，报旗后你裁决） | 变 `retired`，从活跃区删除 |
| **强制移除**（你直接判） | 变 `retired`，理由必写 |
| **合并**（`merge --keep A --drop B`） | 被并的标 `merged`（`merged_into` 指过去），refs 取并集；**无理由不许合** |
| **过期**（`expire [--days 40]`） | 候选 40 天没人认领 → `expired`，进 `l1_history`（不删） |
| 以上各种 | 全文搬进 `记忆/L3/L1-历史.md`（只追加），记期号与原因 |

**为什么搬走不删**：以后要说"她曾经是这样、后来改了"，得拿得出证据。

## 8. 权限

| 角色 | 能做什么 |
|---|---|
| **agent** | 只能**产出候选**（写候选区）；不能签字、不能改 state、不能改 rule 文本 |
| **maker** | 签字（候选→生效）、裁决回收、批准毕业 |
| **脚本** | 校验（refs 存在性、行数、字段完整性）、追加 changelog、报旗 |

机器可校验的三条硬线：**① active ≤10 行；② 每条 refs 都能在 L3 解析到；③ 每条都有 reclaim**。任何一条不满足，签字也不生效。
