# 查询代理：小模型预算（定稿）

写于 2026-10-28 · 对应待办「已定 · 未执行 #9」
契约见 `规格/查询代理-契约.md`；本文件只定**花多少、怎么止损**。

---

## 1. 一句话

> **检索永远不花模型的钱；只有"要不要查、怎么查"这一层才调模型，且一轮最多一次、一会话最多四次。**

## 2. 什么时候调模型

| 情形 | 调不调 | 说明 |
|---|---|---|
| 有时间词 + 有 ≥1 关键词 | **不调** | 规则直接出探针计划（0 成本） |
| 完全没有回忆信号（观点/假设/寒暄） | **不调** | 规则直接 `need_more` |
| 信号模糊（"上次那个"、多个候选主题） | **调 1 次** | 要它判断"该不该查、往哪个方向查" |
| 探针第 2、3 次（换角度） | **不调** | 仍按规则走，不追加模型 |

**结论：一个"顺利的回忆"通常花 0 次模型调用。**

## 3. 硬上限

| 项 | 上限 | 超了怎么办 |
|---|---|---|
| 每次 recall 的模型调用数 | **1** | 直接用规则结果，不再请示模型 |
| 每次会话的模型调用数 | **4** | 第 5 次起降级为纯规则 + `need_more` |
| 单次输入 tokens | **≤1200** | 超了截候选线索，不截问题原文 |
| 单次输出 tokens | **≤200** | 只要 JSON 计划，不要解释 |
| 单次超时 | **8 秒** | 超时 = 失败，走降级 |
| 单条会话的 recall 次数 | **6** | 第 7 次直接 `need_more`（"今天查得有点多了"） |

## 4. 降级链（任何一步失败都不许报错给用户）

```
调模型 → 失败/超时/超预算
        ↓
纯规则出计划（宽窗 + 单关键词）
        ↓
仍然无命中
        ↓
need_more：明说"日志里没找到"，问一个具体线索
```

**任何情况下都不许**：编一条"记得"、把半份结果当全份、告诉用户"系统出错了"。

## 5. 配置（插件「设置→人格」里可改）

| 键 | 默认 | 含义 |
|---|---|---|
| `l3q.enabled` | `true` | 关掉就纯规则，零模型调用 |
| `l3q.model` | 跟随当前会话模型 | 独立指定时填模型名 |
| `l3q.maxPlansPerRecall` | `1` | 每次检索最多几次规划 |
| `l3q.maxPlansPerSession` | `4` | 每次会话上限 |
| `l3q.maxRecallsPerSession` | `6` | 每次会话最多查几次 |
| `l3q.timeoutMs` | `8000` | 单次超时 |

**开关的语义**：`enabled=false` 不是"不能用"，是"只用规则"——她照样能查，只是判得更笨。

## 6. 记账（写进 `_查询审计.jsonl`）

```json
{"ts":"2026-10-28T12:30:11","q_hash":"a1b2c3d4","when":"上周","keywords":["壳"],
 "status":"found","hits":2,"probes":2,"plans":1,"model":{"calls":1,"in_est":860,"out_est":120,"ms":1400}}
```

- `plans` = 这一轮调了几次规划模型；`probes` = 检索了几次；
- `model` 只在真调过模型时出现；
- **审计里不记原话**（只 hash + 前 20 字，沿用 L3 规范 §5.4）。

## 7. 验收（实现时要跑）

| # | 用例 | 期望 |
|---|---|---|
| B1 | 有时间 + 有关键词 | `plans=0`，直接出计划 |
| B2 | "上次那个"（模糊） | `plans=1` |
| B3 | 同一会话连查 5 次 | 第 5 次起 `plans=0`（降级），且 **不报错** |
| B4 | 模型超时（mock 8s+） | 走规则，结果仍可用 |
| B5 | `l3q.enabled=false` | 全程 `plans=0`，功能不消失 |
| B6 | 第 7 次 recall | `need_more`，文案是"今天查得有点多了" |

## 8. 成本量级（自己乘单价）

一次规划 ≈ **960 input + 150 output tokens**。
按一天 20 次 recall、其中 40% 需要规划算：**8 次/天**，即约 **7.7k input + 1.2k output tokens/天**。
量级上是"每天几分钱到几毛钱"，**不会成为主要成本**——主要成本永远是写稿和多轮对话本身。

> 如果哪天发现它成了成本，说明规划调用次数失控了：先看审计里的 `plans` 分布，再调 `maxPlansPerSession`。
