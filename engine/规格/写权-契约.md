# 写权契约（v1 · 2026-10-29）

> 判据只有一个：**哪一次签发**。不是哪台机器，不是哪个客户端，不是哪种模式。

---

## 1. 判据

| 项 | 定 |
|---|---|
| 单位 | **会话级**（token 绑 session id） |
| 签发者 | 只有 maker，或 maker 明确授权的签发器 |
| 内容 | 给到哪几个**具体工具** + 到期时间 + 来源客户端（仅记录） |
| 默认 | **没有签发 = 只读** |
| 机器 | **只记录，不参与判断** |

淘汰的旧判据（写在这里防回归）：

| 已废 | 为什么废 |
|---|---|
| 「完整模式能写」 | 模式是打包方式，不是身份 |
| 「本机能写」 | QQ 那条路从腾讯进来，落到的还是同一台机器 |
| 「客户端是 DSH 就能写」 | 客户端可伪造、可转发 |

---

## 2. 工具集分级

| 级别 | 工具 | 签发要求 |
|---|---|---|
| **只读** | `get_persona` / `search_memory` / `recall` / `search_notes` / `get_snapshot` / `list_t1` / `preflight` / `scan_draft` | 无需签发 |
| **写记忆** | `stage_memory`（提案）/ `note_add` / `note_daily` | 需 `write:memory` |
| **写过程** | `write_handoff` / `mark_close_pending` | 需 `write:handoff` |
| **写状态** | `set_snapshot` / `wb_retire` | 需 `write:state` |

**不签发整包**：只签发"用到的那几项"，`write:memory` 不等于 `write:state`。

---

## 3. 失败方向

| 情形 | 行为 |
|---|---|
| token 缺失 | 拒（只读） |
| token 过期 | 拒 |
| token 工具集不包含该工具 | 拒，并说明缺哪一项 |
| 判不出来（比如来源不明） | **拒** |

**永不默认放行。** 拒绝文案必须写清：缺哪项签发、该找谁签。

---

## 4. 记账（签发本身要留痕）

签发事件写 L3 `_签发.jsonl`：

```json
{"ts":"2026-10-29T00:50","session":"…","client":"DSH","grants":["write:handoff"],
 "expires":"2026-10-29T02:50","by":"maker","reason":"今晚收尾"}
```

- 只追加，不改；
- **会话结束不删**；
- 撤销 = 追加一条 `revoked`，不删原记录。

---

## 5. 外部通道

| 通道 | 写权 |
|---|---|
| 只读 MCP（HTTP/stdio） | **永不签发**（服务端不注册写工具） |
| 粘贴启动包 | 包里没有写工具，天然只读 |
| 千问/QQ/其它客户端 | 与 DSH **同等**：没签发就是只读 |

---

## 6. 与回退的关系

回退（`--full` / 旧快照）**不改变写权**：换一份包，不等于换一次签发。

> 同一会话里换了包，写权仍是那一张 token。要加权限，重新签发。
---

## 7. 签发时效（2026-10-29 · {角色名}要求定死）

> 不留模糊。**不写死，实际就会有人做成默认放行。**

| 模式 | 内容 | 适用 |
|---|---|---|
| **A 逐次点** | 每次写操作前 maker 点一次 | `write:state`（改任务看板、退休）**只能这样** |
| **B 开场短时效** | 开场签一次，**4 小时**，只含 `write:handoff` + `write:memory` | 每晚收尾 |

**B 的六条硬约束（缺一不可）**

1. 只能**开场**签，中途不许补签；
2. **到期自动失效**，不自动续；
3. 工具集固定两项，**不可扩**（`write:state` 永不在内）；
4. **每个开场窗口可签 1 次**（同会话不重复签）；**24 小时内累计授权 ≤ 8 小时**；超限后**不禁止写，只禁止 B 模式**——退到 A 模式逐次点，窗口滑出后 B 自动恢复；
5. 记账：session、客户端、工具集、到期、理由；
6. **写权与包解绑**：换包不换权。

## 8. 防「默认放行」（与 N2 / N5 同级）

| 闸 | 做法 |
|---|---|
| 文档 | 「默认放行」进禁止清单 |
| 自检 | `preflight` 断言：有写操作却无有效签发 → **报错**（不是警告） |
| 用例 | `selftest.py` 加一条：无签发写 handoff 必须被拒 |

## 9. 模型申请取卡的额度（对应「触发」的第三条）

| 项 | 定 |
|---|---|
| 每会话上限 | **2 次** `request_card` |
| 每次上限 | **1 张卡** |
| 预算 | 单卡 ≤ 卡 `budget_han`；装完总预算仍受任务 `budget_han` 约束 |
| 理由 | 必需（为什么需要 + 打算做什么） |
| 重复 | 同一张卡被拒后本会话不许再申请（防死循环） |
| 冷却 | 同卡 10 分钟 |
| 超额度 | 拒 + 回话「要加卡请让 maker 追加」 |
| 记账 | `requested_by: model` + 理由 + 拒绝原因 + 剩余额度 |

## 10. 校验位置：在执行处，不在开场（2026-10-29 · {角色名}指出）

> `preflight` 只在开场跑。签发四小时后到期，那一刻的拒绝必须由**写工具自己**判断。
> 否则就是"开场合法、半夜越权"。

| 位置 | 做什么 | 不做什么 |
|---|---|---|
| `preflight`（开场一次） | 体检：有没有签发、工具集、到期时间、快照是否存在 | **不是唯一闸** |
| **每个写工具调用前**（执行处） | 校验 token 未过期 + 含该工具 + 未撤销；不过就拒 | 不依赖开场结果 |

三条附则：

1. **到期即拒**：不问"刚才是谁签的"，只看这一刻有效没有；
2. **越权尝试记账**：被拒的写调用写进 `_签发.jsonl`（含 session、工具、原因），不静默；
3. **不续期**：执行处发现快到期，只报"要到点了"，**不许自动续**。

---

## 11. 装与卸的计数（2026-10-29 · {角色名}指出会被误读）

> 只能加不能卸的话，「每会话 ≤2 次」实际是"替换次数"，会被读成"累计次数"。

| 动作 | 是否可做 | 怎么计数 |
|---|---|---|
| `request_card`（装） | 可以 | 计入**申请次数**（≤2/会话） |
| `unload_card`（卸） | **可以**，不需理由 | 计入**变更次数**（≤4/会话），**不占**申请额度 |
| 同一张卡装回 | 可以 | **再计一次申请**（防反复装卸抖动） |
| 一次申请多张 | 不行 | 每次 1 张 |

所以两个数分别表述：

- **申请 ≤2 次**（这是"几回"，不是"几张"）；
- **在场卡变更 ≤4 次**（装+卸合计）。

> 写清这两个数，避免下一个人把它读成"总共只能碰两张卡"。
---

## 12. 超限不等于禁写（2026-10-29 · {角色名}指出）

> 「24 小时 ≤8 小时」封顶后，第三个窗口就签不出 B 了。**那时不能禁写，要退到 A。**

| 状态 | B 模式（短时效） | A 模式（逐次点） |
|---|---|---|
| 24h 累计未超 | 可签 | 可用 |
| **24h 累计已超** | **不可签**（拒） | **仍然可用** |
| 窗口滑出后 | 自动恢复 | — |

**原则：上限管的是"批量的额度"，不是"能不能写"。**

任何"到点就彻底不许写"的实现，都是把额度做成了惩罚——不允许。

---

## 13. 记账通道必须在系统侧（2026-10-29 · {角色名}指出）

> 如果被拒的那一次，记账本身也要签发，它就记不下来。

所以 `_签发.jsonl` **不走她的写权**：

| 项 | 定 |
|---|---|
| 写入者 | **宿主（her-host / 装配器）**，不是她 |
| 依赖 | **不依赖 token**：token 缺失、过期、被撤，照样写 |
| 时机 | **先记"尝试"，再校验，再记结果**（两步都落盘） |
| 内容 | session、工具名、来源客户端、结果（allowed / denied）、拒绝码 |
| 属性 | 只追加；不删不改；不受她的额度限制 |
| 失败 | 记账本身失败 → **按失败处理**（拒绝这次写），并额外落一条到 stderr 日志 |

一句话：**审计通道不能挂在被审计的东西上。**

---

## 14. 写操作的固定次序

```
① 系统侧记「尝试」（无签发也照记）
② 执行处校验 token（过期 / 工具集 / 撤销）
③ 校验通过 → 执行；不通过 → 拒
④ 系统侧记「结果」（allowed / denied + 码）
```

②失败也必须走到 ④。缺 ④ 的实现视为未完成。

## 15. 简易模式：免签 + 免核实（2026-10-30 · maker 定）

前面十四节讲的都是**严格模式**。简易模式是给"自己用、嫌点票烦"的场景开的，但**只放开两件事**。

### 15.1 放开什么

| 环节 | 严格 | 简易 |
|---|---|---|
| 写记忆 / 写交接要不要票 | 要签发 | **免签**（自动放行，审计记 `simple-auto`） |
| L2 待确认区要不要签字转正 | 要 maker 签 | **白名单类目免核实**（记 `auto-approve`） |

### 15.2 类目白名单（判据是类目字段，不是内容语义）

| 类目 | 简易模式 |
|---|---|
| 工作方式 / 成长记录 / 偏好 | ✅ 自动转正 |
| 反思 / 总结 | ✅ 自动转正 |
| 含他人原话 | ✅ 自动转正 |
| 含具体数字（播放/期数/日期） | ✅ 自动转正 |
| **身份与来历** | ⛔ **始终要签** |

- 不在白名单里的类目 → 仍进待确认区。
- **任何模式都要人工的两处**：改 L0 人格卡、恢复任务卡。

### 15.3 免核实≠免留痕

- 每条自动转正写 `l2_changelog`，`action=auto-approve`，detail 记类目与理由；
- `preflight` 报「自动转正：最近 7 天 N 条」，并给抽检命令；
- 错了用 `memory_db.py supersede --old <号> --new <号>` 回滚，原件（raw）不动。

### 15.4 为什么不放开"身份与来历"

改身份是这套系统里**最贵**的操作：它同时影响注入包、L0 提案链路、以及"她是谁"的判断。
数字写错了改一条就行，身份写错了整套东西都会歪。

### 15.5 切换与留痕

```powershell
python 脚本/policy.py set simple --why "自己用，嫌烦"
python 脚本/policy.py set strict --why "要发版了"
python 脚本/policy.py                     # 看当前等级 + 白名单
```

- 等级存在 `规格/审核等级.json`；每次切换写 `记忆/L3/_审核等级.jsonl`（谁切的、为什么）；
- **切换本身不需要审批**——它是配置，不是写数据。
