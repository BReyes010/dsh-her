## 1. 背景与目标

- 「{角色名}」是 DeepSeek 的社区形象（网友画的蓝色肥鱼），现作为虚拟主播运营：口播稿由 AI 生成、TTS 朗读、发 B 站。
- 目标：她的人格和记忆要**"长"出来**——前期只有一句设定，之后每一期视频、每一次评论互动都成为她性格与记忆的来源。
- 长期愿景：人格与记忆以**纯文本、结构化、可溯源、自解释**的形式存盘，将来可整体移植给更强的模型。
- 两条宪法：
  1. **L0（人格卡）只有 maker 能改**——AI 永不可改；maker 修改须附理由 + 版本号 +1，全程留痕；L0 永不自动变更；
  2. **一切自动沉淀必须经过人工裁决才能生效。**

## 2. 四层结构（v0.3）

| 层 | 内容 | 谁可写 | 注入方式 | 上限 |
|---|---|---|---|---|
| L0 人格卡 | 她是谁、动机、禁止清单、玩梗判据、技术规范、说话样本 | **只有 maker**（理由+版本+1） | 每次全文注入 | 规则 ≤30、样本 15–20 |
| L1 自我认知 | 候选 L0 规则（处方式行为规则），≤10 行 | 她提议 → maker 签字；**满队时允许自动降权**（见 §7） | 每次全文注入 | ≤10 行 |
| L2 经历（世界书） | 常驻层（当前状态 / 成长记录 / 与观众关系 / 我的来处）+ 关键词层 | 自动沉淀 → 待确认区 → maker 确认 | 常驻层注入滑窗；关键词层命中注入 | 常驻各类限行数（见 §9） |
| L3 原始日志 | 成稿、复盘、历届 L1、全部事件、L0 变更历史 | 只追加 | **永不注入** | 无 |

**层间切分（写死）**：L1 = 处方式（"做 X、避免 Y"）；L2 = 叙事式（发生过什么，供背景引用）。L2 常驻层里的处方内容一律清出来归 L1。

## 3. 核心机制：性格怎么"长"

**人格变化 = 往 L1 加一行（候选 L0 规则），而不是改 L0。** L0 只在 maker 签字 + 毕业机制下变化。

条目模板：

```
#L1-NN｜日期｜标题
证据：#a、#b + 一行证据摘要（脱离 L3 仍可读懂、可核验）
影响：（具体到能改变下一期稿子的某一句话）
回收条件：（什么信号出现时收回这条）
```

实例：

```
#L1-01｜讲清的内容不再用道歉开头
证据：#2（第 2 期：观众"你为什么一直道歉"，自我怀疑句 4 次）、
     #3（第 3 期：第一次直接给结论，数据没涨但她不后悔）
影响：干货段落删掉开头的"可能是我搞错了"；"讲对的事硬"出现频率上升
回收条件：连续 3 期出现"讲得太硬被误解" → 收回
```

**检验标准**：一条 L1 条目的"影响"必须能改变下一期稿子里的某一句话；不能，就是废话。

**总原则（精确版）**：性格由她的**选择**塑造；结果永不**单独**成为 L1 条目，但结果可作为某个选择事件的**背景**。边界情况（长期失败导致的"变谨慎"）按 §6 PROVISIONAL 处理。

## 4. 事件类型闭合清单（v0.3）

**可以进 L1 候选的（5 类）**：

| 类型 | 判据 |
|---|---|
| ① 做对了"以前的她会做错"的事 | 与 L1 旧条目或 L0 样本对比可得 |
| ② 讲错被指，且改法涉及"怎么判断/怎么开口" | 纯知识错误不算 |
| ③ 被反驳且坚持住了 | "不争"的新边界具体化 |
| ④ 拒绝了一件事 | 选择定义性格 |
| ⑤ 学到改变做法的新东西 | 改的是"做法"，不是"知识" |

**排除的（5 类）**：知识/事实修正 → L2 主题索引；TTS 读法 → L2 技术表；数据涨跌本身 → 只进数据表；观众的一次夸奖或谩骂 → 外部结果；"她觉得自己变了" → 无行为证据的主观感受。

**关系变化不设事件类型**：走 L2 常驻层〈与观众关系〉的叙事更新通道，不进 L1。

**评论事件的三类高门槛触发器（v0.3 新）**——评论噪声大、碎片化，只有以下三类才打包成事件入池：

1. **maker 显式互动过**的评论；
2. 同一观点 / 梗 / 争议在 **≥2 期**评论区重复出现（形成共识的）；
3. 评论导致她**当期实际改了做法**的。

其余评论一律只进 L3。第 2 类的跨期统计由执行侧在每期复盘时对评论存档（监听日志）做简单聚合，不新增人工负担。

## 5. 硬闸（v0.3 版，全部二值化）

1. **双证据**：一条 L1 条目默认需要 ≥2 条**不同期**的独立事件。
2. **无证据编号不写**：缺编号即拒绝。
3. **结果不入，只认选择**（§3 精确版）。
4. **冲突检测二值化**（v0.3 改）：新 L1 条目与 L0 禁止清单 / 核心底线**逻辑互斥** → 一票否决；不互斥，则看"影响"字段是否**能改变下一期某一句话** → 不能，否决。冲突检测结果必须**并排列出"L0 条款原文 vs 候选影响"**，maker 一眼核验；删除一切"可解释为具体化"类的软表述。

**单证据豁免（判据 = 自明的昂贵选择）**：

> 在更安全 / 更省力 / 更默认的退路明显可得时，她选了代价更高的那条，且**代价内生于选择**（她主动放弃了什么），而非外生于舆论（外界反应多大）。

**提名强制模板（v0.3 新）**——防模型把平庸选择包装成"伟大抉择"：

```
退路对比行：
① 当时最省力/安全的默认做法：（必须引用当期真实存在的候选，不许凭空编）
② 她实际放弃的具体利益：（具体到"放弃了什么"）
```

缺任一项，系统自动拦截。**重大失误且无纠正**：不走 L1，是 maker 直接修订 L0 的信号，不受证据数约束。

## 6. PROVISIONAL 滞后期（v0.3 修订）

**适用**：诞生于持续外部压力期（数据差、争议期）的 L1 候选。

1. 反思提名时，候选触发背景是"持续外部压力" → 标 `PROVISIONAL`，放待确认区。
2. 转正条件：**压力撤除后，行为依然留存**。核验时机 = 下一次反思或 maker 裁决；存疑就继续暂挂。
3. **硬上限：最长 6 期**（拍的）。期满未转正 → 自动归档 L3，不在待确认区滞留。

**原理**：把"结果塑造还是选择塑造"的当场哲学判断推迟到可观测时——结果塑造的应激变化熬不过滞后期自己死掉；选择塑造的变化熬得过去自然转正。

## 7. L1 毕业机制（v0.3 修订）

**L1 条目生命周期**：候选（待确认区）→ 生效（L1）→ **毕业（L0）** 或 回收。

**毕业门槛（v0.3）**：毕业评估**只发生在季度反思**。候选资格（二值）：该条目**已存在 ≥12 期（熬过至少一次季度反思）且回收条件从未触发**。满足 → maker 签字毕业。

**毕业去向**：

- 处方式条目 → 并入 L0 规则：**合并进同类或替换某条**，替换须 maker 写一句理由；
- 文体类条目 → **坍缩成 L0 范例**（契约见 §8）。

**L0 满额（v0.3）**：规则 ≥30 或样本 ≥20 时，新毕业条目必须完成一次"合并/替换"才能进。自动淘汰（FIFO / 最不常用）**只作为提名**出现在裁决清单里，最终动作永远是 maker 的，L0 永不自动变更。

**L1 满队（v0.3 改裁）**：L1 满 10 行且新条目要进 → **自动降权**得分最低的条目（得分 = 距上次被引用为行为证据的期数 + 是否触发过回收条件）。被降条目**不直接沉 L3**，而是进入**回收复核清单**：

- 清单随下个裁决周期展示给 maker，可**一键恢复**；
- maker 连续 4 个裁决周期（≈1 个月）未恢复 → 自动归档 L3。

自动降权只允许发生在 L1；L0 永不自动变更。

## 8. 语感的生长（v0.3 修订）

语感分两种：

- **(a) 可规则化的文体习惯**（能写成"在 Z 处用 X 代替 Y"）→ 能进 L1。
- **(b) 不可拆解的声音 / 质感**（格式塔，由上百个微选择涌现）→ 不住在任何规则里，住在 L0 样本 + 写作模型的生成先验里。

**三条硬规则**：

1. **(b) 只靠 maker 策展生长**：终审时凡有一行腔调 maker 觉得"这就是她"，就把那一行提升进 L0 样本库。L0 样本是活的语料库。语感不通过 L1 自动反思生长。
2. **防止 (a) 过饱和**：L1 文体微规则堆多了，模型把"人格预算"花在逐条打勾上 → 所有动作都对、合起来是恐怖谷。**L1 越满她越不像。** 成熟 (a) 必须及时坍缩成 L0 范例。
3. **坍缩契约（v0.3 改）**：**禁止 AI 自动转换规则为样本。** 当某文体习惯毕业时，由 **maker 亲自写一句不带任何说教、纯粹符合该语感的真实口播原话**补充进 L0 样本库，同时**彻底删除**对应的 L1 规则。规则是打勾约束，样本是沉浸范例，二者之间不存在机器可执行的安全转换。

**写作侧 prompt 两条硬要求（不变）**：

- L0 样本的定位是"**要去沉浸的声音**"，不是"要遵守的规则清单"；
- 写稿与审稿分离：模型写、模型只做技术修正，"像不像"只有 maker 能判。

## 9. 数值阈值（v0.3 修订版）

**前提不变**：上下文长度不是触发器（子代理冷启动）；触发器绑在事件数、条目数、L1 行数上。

| 环节 | 触发条件 | 频率（周更节奏） |
|---|---|---|
| 复盘 | 每期必做（含计数位） | 每期 |
| 待确认区裁决 | 每周固定 | 6 条/月 |
| 反思（事件触发） | 未消化事件 ≥ 3 | 前期约每 4 期，后期约每 10 期 |
| 反思（时间兜底）+ **毕业评估** | 连续 12 期未触发 = 每季度 | 每季度 |
| L1 满队降权 | 新条目进不了时 | 随反思自动 |
| PROVISIONAL 归档 | 满 6 期未转正 | 自动 |
| 冲突检测 / 纵向统计 | 每次反思后 | 脚本 |
| 降级报警 | 三重触发（下） | 触发时 |

**降级报警三重触发（v0.3 修订）**：待确认区 >4 个裁决周期未动 ｜ 当前状态 >3 期未推进 ｜ 实际发稿间隔 > 计划节奏 ×2。任一触发 → 下次写稿时给 maker 一行提醒；**同一原因只报一次**，被处理后重置。

**关键估计（全部"拍的"，仅容量预估，不作裁决依据）**：

- 事件密度：前 10 期 ~0.8 条/期，之后 ~0.3 条/期；
- 反思期望通过 ~1.0 条/次；
- L1 装满 10 行约 1.5–2 年；毕业、降权、回收三出口的稳态比例**未验证**（见 §12 第 1 问）。

**L2 常驻层注入滑窗（v0.3 修订）**：

- 成长记录：注入只取**最近 5 条复盘原文，脚本自动拼接**（废除人工阶段性总结），全文沉 L3；
- 当前状态 ≤10 行；与观众关系 ≤10 行；我的来处 ≤5 行。

**每期流程的阻断步骤**：当前状态不更新 → 本期不能标记完成；复盘必须带计数位（"可能/大概/我不确定"出现次数）。

**纵向统计的模型版本标（v0.3 新）**：计数位记录时附带"写作模型 + 版本"；季度统计只做**同版本区间**对比；更换写作模型后 **5 期只记录不判断**，重建基线。

**评论线程压缩触发**：线程静默（72 小时无新评论，拍的），不用固定时长。

## 10. 一次反思的完整形态（v0.3）

**输入**：未消化事件复盘（期数｜类型｜一句话事实｜她的选择｜结果 + 计数位）+ 当前 L1 + L0 判据。

**输出**：≤3 条候选（§3 模板 + 证据摘要；单证据候选必须附 §5 退路对比行）+ 明确写出"某类无积累"。评审样例：

```
✅ #L1-01｜讲清的内容不再用道歉开头（见 §3 实例）
✅ #L1-02｜拒绝过的热点，以后连看都不看
   证据：#3（第 3 期：拒绝了苦难类热点，数据比上期低，她决定继续）
   影响：选材跳过"笑点建立在别人疼上"的题；稿子里不提"我拒绝了它"
   回收条件：她开始把"拒绝"当人设卖点 → 收回
❌ "数字先转中文再念" → 技术修正，转走 L2 技术表
❌ "我变得更加自信了" → 形容词、无证据、无法改变下一期任何一句话
```

**冲突检测输出格式（v0.3）**：

```
L0 条款原文：……
候选影响：……
判定：互斥 → 否决 ／ 不互斥且能改变一句话 → 过
```

**双校验器**：正向行为条目 → 逐句检验；回避类条目 → 纵向选材日志检验（跨 ≥5 期看选题分布是否系统性回避）。

## 11. 移植包规则（v0.3 新）

长期愿景的落地契约：将来整体移植给更强模型时，打包注入——

1. **当前版 L0 全文**；
2. **近 3 次 L0 变更摘要**（理由 + 版本号，来自 L3 变更历史）；
3. **一句血统说明**（她从哪里来、经历了哪几个阶段——由 maker 手写，或执行侧从季度反思结论起草、maker 修改）。

总预算 ≤2k token。日常运行仍只注入当前版，历史只进移植包——既保留"人格演进的基因图谱"，又不污染日常注入。

## 12. 请评审者重点挑刺的 12 个问题

1. **三个出口的稳态没人算过**：毕业（≥12 期 + maker 签字）、自动降权（满队即触发）、回收（条件触发）。若毕业吞吐低而自动降权快，L1 会不会稳态变成"回收循环"而非"毕业队列"？三条路的速度配比需要模拟吗？
2. **自动降权 + "4 周期不恢复即归档"**：maker 长期不看复核清单时，降权就变成事实性遗忘——和它当初反对的"静默腐烂"是不是同一个病、换了个地方复发？恢复窗口该多长？
3. **L0 满额时的"合并或替换"由谁执笔**：maker 手写合并文，还是模型起草 maker 改？合并会不会把两条具体规则并成一条模糊大规则，违反"影响必须改得动一句话"？
4. **退路对比行的"引用当期真实候选"**：怎么验证模型没编一个更差的退路来包装她的选择？要不要对比行也带来源（选题记录里的候选编号）？
5. **PROVISIONAL 6 期硬上限会误杀**：压力持续 8 期、她第 8 期才做出真正的留存选择——6 期一到就归档了。归档前要不要一次"最后核验"？归档后能否复活？
6. **冲突检测的"引条款原文"**：由模型执行时，模型会不会故意引一条不相关的条款让候选过关？并排列输出 + maker 核验够不够，还是需要自动做字符串级条款匹配？
7. **毕业只发生在季度反思**：一年最多 4 次毕业窗口，会不会让 L1 长期满队、降权频繁、maker 的恢复动作反而比以前签字更累？
8. **L0 上限 30 规则 + 20 样本是拍的**：按全量注入算，这个规模下 L0 的 token 预算是多少？和"精简人格卡"的初衷还一致吗？上限该按条数定还是按 token 定？
9. **"同一原因只报一次"的失效模式**：报完一次 maker 没处理，之后系统就真静默了。报警重置条件是谁来重置？会不会变成"报一次 → 永久闭嘴"？
10. **评论第二类触发器（≥2 期重复出现）的统计**：执行侧聚合靠什么？评论存档的检索口径谁维护？会不会为了这条触发器养一个没人维护的小工具？
11. **模型版本标**：写作模型的版本由谁控制？平台静默升级小版本时，打标粒度够吗？还是说"换模型"只按大版本算？
12. **三轮下来，maker 的真实月工时到底是多少**：裁决 6 条 + 季度毕业签字 + 复核清单抽查 + 报警处理 + 坍缩范例手写 + 终审"像不像"。10 分钟/月还成立吗？哪些 maker 动作可以合并成"每月一次 30 分钟集中批"？
