## 1. 背景、目标与宪法

- 「{角色名}」是 DeepSeek 的社区形象，现作为虚拟主播运营：口播稿由 AI 生成、TTS 朗读、发 B 站。
- 目标：她的人格和记忆要**"长"出来**；长期愿景是整体移植给更强的模型。
- **宪法（三条，v0.4 版）**：
  1. **L0 只有 maker 能改**（理由 + 版本号 +1），AI 永不可改，永不自动变更；
  2. **一切自动沉淀必须裁决生效**；
  3. **已生效条目的降权、归档、改写与新增同权**——必须是 maker 的肯定性动作；超时默认**维持现状**。（v0.4 补丁：撤销与新增同等受保护，堵住"自动撤销"这条后门。）

## 2. 四层结构（v0.4）

| 层 | 内容 | 谁可写 | 注入方式 | 上限 |
|---|---|---|---|---|
| L0 人格卡 | 她是谁、动机、**底线/禁止**、**行为规则**、玩梗判据、说话样本 | **只有 maker**（理由+版本+1） | 每次全文注入 | 底线 ≤8、规则 ≤12、样本 ≤12；人格块 ≤1200 token（硬顶 2000） |
| L0′ 技术前缀 | TTS 读法、数字转写、句长、标点规范（**v0.4 移出 L0**） | maker | 每次注入，**独立前缀、不计人格块预算** | 无（技术文档，不与人格抢注意力） |
| L1 自我认知 | 候选 L0 规则（处方式），≤10 行 | 她提议 → maker 签字 | 每次全文注入 | ≤10 行；满队见 §7 |
| L2 经历（世界书） | 常驻层 + 关键词层 | 自动沉淀 → 待确认区 → maker 确认 | 常驻层注入滑窗；关键词层命中注入 | 常驻各类限行数（§10） |
| L3 原始日志 | 成稿、复盘、历届 L1、全部事件、L0 变更历史 | 只追加 | **永不注入** | 无 |

**层间切分（写死）**：L1 = 处方式（"做 X、避免 Y"）；L2 = 叙事式（发生过什么）。L2 常驻层里的处方内容一律清出来归 L1；技术规范归 L0′，不归任何人格层。

## 3. 核心机制：性格怎么"长"

**人格变化 = 往 L1 加一行（候选 L0 规则），而不是改 L0。**

条目模板：

```
#L1-NN｜日期｜标题
证据：#a、#b + 一行证据摘要（脱离 L3 仍可读懂、可核验）
影响：（具体到能改变下一期稿子的某一句话）
回收条件：（什么信号出现时报告 maker，不自动执行）
```

**检验标准**：一条 L1 条目的"影响"必须能改变下一期稿子里的某一句话；不能，就是废话。

**总原则（精确版）**：性格由她的**选择**塑造；结果永不**单独**成为 L1 条目，但结果可作为某个选择事件的**背景**。边界情况按 §6 处理。

---

## 4. 事件类型闭合清单（v0.4）

**可以进 L1 候选的（5 类）**：① 做对了"以前的她会做错"的事；② 讲错被指且改法涉及判断方式；③ 被反驳且坚持住了；④ 拒绝了一件事；⑤ 学到改变做法的新东西。

**排除的（5 类）**：知识/事实修正 → L2 主题索引；TTS 读法 → L0′ 技术前缀；数据涨跌本身 → 只进数据表；观众的一次夸奖或谩骂 → 外部结果；"她觉得自己变了" → 无行为证据的主观感受。

**关系变化不设事件类型**：走 L2 常驻层叙事更新通道，不进 L1。

**评论事件三类高门槛触发器**：① maker 显式互动过；② 同一原句在 ≥2 期评论区重复出现（精确匹配，见 §10）；③ 导致她当期实际改了做法。其余只进 L3。

## 5. 硬闸（v0.4）

1. **双证据**：默认 ≥2 条不同期独立事件。
2. **无证据编号不写**。
3. **结果不入，只认选择**（§3 精确版）。
4. **冲突检测穷举化（v0.4 改）**：候选与 L0 **每一条**底线/禁止并排，全部默认"未判定"；任何一条未勾选 → 不得准入。模型可预填建议，预填**不是**通过——勾选与复核是 maker 的动作。规模小（底线 ≤8），穷举比任何检索/匹配算法都便宜，且删掉了"模型挑选引哪条"这个漏洞本体。

**单证据豁免（v0.4 改：仅 maker 可提名）**：

> 判据 = 自明的昂贵选择：在更安全 / 更省力的退路明显可得时，她选了代价更高的那条，且代价内生于选择。

- **模型不得提名**。提名由 maker 在裁决时手填三字段：
  ① 当时最省力/安全的默认做法（必须引用**决策当时已存在**的编号——选题记录或稿件 diff 的候选 id，反思期补编的编号无效）；
  ② 她实际放弃的具体利益（必须有当期货币痕迹：v2 稿里删掉的段落、候选列表里拒绝的题）；
  ③ 展示方式与冲突检测一致：并排贴源文，不单列转述。
- 无当期痕迹 → 退回双证据。
- **重大失误且无纠正**：不走 L1，是 maker 直接修订 L0 的信号，不受证据数约束。

## 6. PROVISIONAL 滞后期（v0.4 重写）

**适用**：诞生于持续外部压力期（数据差、争议期）的候选。

**两段式时钟（v0.4）**：

1. **压力旗**：由 maker 标记，或二元规则打开（如"连续低于已建立基线"）；**最长 8 期**，防压力旗永不关闭。
2. **旗关后 4 期留存观察**。最坏 8 + 4 = 12 期，**必然撞上一次季度反思**——对齐到已有时钟，不再单独设一个悬空的"6"。
3. 观察期结束时，**下一次反思做一次强制二元核验**："旗关之后这几期，行为还在不在？"不做新的哲学判断。
4. 归档允许，但留**一行墓碑**（主题 + 归档期号）进 L2 索引，**不把 L3 正文注入回来**。同类事件之后入池时，反思输入必须带上这行墓碑。墓碑同时最多 5 行。

**未签字候选可以超时死掉；不许死得无痕迹。**

## 7. L1 队列与毕业（v0.4 重写）

**生命周期**：候选（待确认区）→ 生效（L1）→ 毕业（L0）或 maker 确认回收。

**PIN（v0.4 新）**：年龄 ≥8 期且回收未触发 → **自动 PIN**。PIN 是保护性动作（阻止变更、不变更文本）；任何交换不得触碰 PIN 条目，直到季度毕业评估。

**满队（v0.4 撤回自动降权后）**：

- 新条目进不来 → 停在待确认区，状态 `BLOCKED_CAPACITY`；**已生效条目原样继续注入**（不作为 = 维持已签字文本）。
- 裁决卡二元：**放新的并指定踢掉哪一条** ／ **拒绝新的**。两个都是肯定性动作，无默认删除。
- 被指定踢出的条目：走 maker 确认回收，进 L3 并标原因。

**未签字候选的压力（v0.4 新）**：待确认区挤占条目上限 3 条；超出 → 以"未准入"归档 L3，可凭新证据再提名。挂满 8 个裁决周期未决的，**本期裁决不勾 yes/no 就不能标记完成**（强制二元，禁止默认删除）。8 周期 ≥ 8 周，盖住两次月度批。

**回收只报旗（v0.4 补丁）**：回收条件触发 → 系统报告，maker 确认后才移出 L1。**回收是第三条自动出口，必须堵死。**

**毕业（单一时钟）**：只在**季度反思**检查：期龄 ≥12 且回收从未触发 → maker 签字毕业。毕业窗口不加（L0 慢变是对的）；若 L1 满员且全是 PIN 条目，那是**健康队列**，新候选继续等，不是故障。

## 8. L0 满额与合并契约（v0.4 重写）

**默认路径是替换，不是合并。** 一进一出，禁止语义搅拌。

**合并仅在以下全部满足时允许**：

1. 同族（都是处方，或都是底线）；
2. **蕴含测试卡**：父规则 A、B 各写一句它们会改掉的下一期原话；子规则必须对这两句给出**相同判定**，否则系统拒绝合并；
3. **子规则正文由 maker 亲笔重写**。模型只提供 diff 和测试卡，不提供可直接签字的终稿。

**提名信号（三选一，禁止"引用次数"）**：

- 两规则的测试句重叠；
- maker 标注"这已经不是她"；
- "若它还在 L1，回收条件本已触发"。

## 9. 语感生长（v0.4 不变）

- **(a) 可规则化的文体习惯** → 能进 L1；**防止过饱和**（L1 越满她越不像，成熟 (a) 必须及时坍缩）。
- **(b) 不可拆解的声音/质感** → 只靠 maker 策展：终审时凡有一行腔调"这就是她"，提升进 L0 样本库。
- **坍缩契约**：禁止 AI 自动转换规则为样本；maker 亲手写一句不带说教、符合该语感的真实口播原话进 L0，同时彻底删除对应 L1 规则。
- **写作侧两条硬要求**：L0 样本 = "要去沉浸的声音"，不是规则清单；写稿与审稿分离，"像不像"只有 maker 能判。

## 10. 数值阈值（v0.4）

**前提不变**：上下文长度不是触发器（子代理冷启动）。

| 环节 | 触发 | 频率（周更） |
|---|---|---|
| 复盘 | 每期必做（含计数位） | 每期 |
| 待确认区裁决 | 每周固定 | 6 条/月 |
| 反思（事件触发） | 未消化事件 ≥ 3 | 前期约每 4 期，后期约每 10 期 |
| 季度反思 + 毕业评估 | 每 12 期 | 每季度 |
| 回收报旗 | 回收条件触发 | 报旗，maker 确认才执行 |
| 冲突检测 / 纵向统计 | 每次反思后 | 脚本 |
| 降级报警 | 谓词触发（下） | 升级式 |

**关键估计（"拍的"，仅容量预估）**：事件密度前 10 期 ~0.8 条/期、之后 ~0.3 条/期；反思期望通过 ~1.0 条；**L1 装满 10 行 ≈ 50–60 期（12–14 个月）**。

**降级报警（v0.4 重写）**：

- 触发谓词：待确认区 >4 个裁决周期无条目状态变化 ｜ 实际发稿间隔 > 计划 ×2（周更 = >14 天）。
- **重置条件只有一条：底层谓词变假**（条目状态变化、正文 hash 变化、发稿间隔回到 ≤ 计划 ×2）。禁止"知道了"按钮。
- 升级链：同会话不重复刷；跨会话升级——第 1 次一行提醒 → 第 2 次变成**阻断项**（不勾不能完成本期）→ 第 3 次仍阻断并在日志头写 STALE。
- "当前状态"独立报警已删除（每期硬阻断保留：不更新不能标记完成）。

**评论聚合（v0.4 改）**：每期结束，脚本对评论存档做规范化**精确字符串匹配**（去标点、最短 8 字），跨 ≥2 期出现的原句列入裁决文档。脚本失败 → 写"聚合失败"，本触发器跳过，不阻断发稿；零精确匹配 = 零触发，可接受。未来若改语义聚类：门槛提到 ≥3 期，且**必须由 maker 用一句话命名这个共识**——那一句才是事件，命名不自动化。

**版本标（v0.4 改）**：每次写稿由脚本自动落 `writer_build = (api 返回的 model 字符串, prompt 文件 hash, decoding 预设名)`，人不打标。接口只给稳定别名 → 标 `unversioned`，涉及它的区间禁止对比。重建基线触发：模型族变 / prompt hash 变 / decoding 预设变 / maker 显式标记大版本切换。静默升级不假装可检测：每期记录原始字符串，季度 diff 发现别名字符串变过 → 该区间标 `TAINTED`，不做对比。**隔离长度 = max(8 期, 一个完整反思周期)，切换后第一次反思禁止做纵向判断。**

**L2 常驻注入滑窗**：成长记录注入只取最近 5 条复盘原文（脚本自动拼接），全文沉 L3；当前状态 ≤10 行；与观众关系 ≤10 行；我的来处 ≤5 行。当前状态由复盘脚本起草，**maker 只改错、不从零写**。

## 11. 一次反思的完整形态（v0.4）

**输入**：未消化事件复盘（期数｜类型｜事实｜选择｜结果 + 计数位）+ 当前 L1 + L0 判据 + 相关墓碑行。

**输出**：≤3 条候选（§3 模板 + 证据摘要）+ "某类无积累"。

**冲突检测输出格式（v0.4 穷举表）**：

```
候选影响：……
底线逐条勾选：
□ 底线1「不与观众对骂」—— 候选与其关系：[未判定]
□ 底线2「……」
……（全部底线，缺一条未勾选 = 不得准入）
```

**双校验器**：正向条目 → 逐句检验；回避类条目 → 纵向选材日志检验（跨 ≥5 期看选题分布是否系统性回避）。

## 12. 移植包规则（v0.4 不变）

移植时打包注入：① 当前版 L0 全文；② 近 3 次 L0 变更摘要（理由 + 版本号）；③ 一句血统说明（maker 手写或执行侧起草 maker 改）。总预算 ≤2k token。日常运行只注入当前版。

## 13. maker 工时预算（v0.4 新，诚实版）

| 动作 | 估时 | 能否进月度批 |
|---|---|---|
| 每期"像不像"终审 | 15–25 分 × 4 ≈ 60–100 分/月 | 不能，必须贴着稿 |
| 每期确认当前状态草稿 | 约 2 分/期（脚本起草，只改错） | 不能 |
| 6 条裁决 | ~25 分 | 能 |
| PIN / 放弃勾选 | 含在裁决 | 能 |

## 14. 请评审者（GPT）重点挑刺的 12 个问题

1. **PIN 的副作用**：自动 PIN 会不会让 maker 更难主动放弃一条其实已过时的规则（PIN 形成"默认正确"的心理惯性）？PIN 与回收报旗的优先级谁高？
2. **BLOCKED_CAPACITY 的空窗期**：新条目在待确认区排队时，她这几期的行为没有新规则约束——排队 4 期以上的候选，证据会变旧、转正时她可能已经又变了。空窗期的漂移算谁的？
3. **蕴含测试卡的公正性**：父规则"各写一句会被改掉的下一期原话"由模型起草时，模型会不会挑两句容易过的句子让合并蒙混过关？测试卡本身需要谁审？
4. **技术前缀的边界**："一行一句"是技术还是风格？L0′ 独立注入后，"技术规范与人格抢注意力"的问题解决了，但新的边界问题会不会从 L0 内部转移到 L0/L0′ 之间？
5. **穷举表会膨胀**：底线现在 ≤8，但 L0 修订会让底线条款缓慢增加——底线到 15 条时，穷举表会不会变成 maker 的批改作业？底线条款自身要不要设上限？
6. **压力旗的二元规则**："连续低于已建立基线"——基线本身就是用数据（结果）定义的，会不会把"结果"从后门放回裁决？
7. **墓碑 5 行上限**：装满后最旧的墓碑被替换，那条 PROVISIONAL 的痕迹永久消失——墓碑要不要也沉 L3？
8. **报警升级到阻断项的终局**：maker 真弃坑时，系统最后一步是"发稿流程卡死"而不是"坏掉"。这个终态可接受吗？要不要定义"幽灵模式"（maker 失联后降级为纯自动 + 显式标注）？
9. **精确字符串匹配的漏报**：同义改写（换个说法）就漏——零触发被定为"可接受"，会不会让"观众共识"这条触发器形同虚设？
10. **unversioned 区间的代价**：若平台只给稳定别名，前期所有统计区间都被禁对比——纵向统计还有没有用武之地？
11. **maker 的操作文档**：季度反思时 maker 的实际动作序列（PIN 复核 → 毕业评估 → 蕴含测试卡 → 亲笔终句 → 二元裁决卡）能不能写成一份照着做的清单？否则文档复杂度本身就成了弃坑理由。
12. **"maker 永在"假设**：整套系统把 maker 当成永在前提。如果 maker 消失一年，这套系统最体面的死亡方式是什么？要不要把"冻结/封存"（人格定格 + 停止生长 + 显式标注）写成正式状态？
