# 流程：改任务看板

> 这份是给**写任务看板的人**看的；注入用的 `入口/任务看板.md` 只留结论。

## 结构：固定五块

1. **现在**——正在做的那一件事，一句话。
2. **已定**——拍板的结论，指针表：`- D-xx｜一句话｜→ 路径`。**只补不删**；过时用 `retire`，不改措辞。
3. **卡在哪**——具体挡路的事，指得出卡在谁身上。
4. **下一步**——编号，最多三条，第一条就是真要动手的。
5. **踩过的坑**——会让下一个人重复犯错的，写死它。

## 三条铁律

- 只放结论，不放过程；细节写指针，别抄正文。
- 判据：**缺了它下一个人会不会做错事？** 会 → 留；只是"知道了更好" → 删。
- 重写先读，把已有「已定」带过来。**宁可重复，不许丢。**

## 命令（不要手写整份）

```powershell
python 脚本\workbench.py set-now "…"
python 脚本\workbench.py decide "一句话" --pointer 路径
python 脚本\workbench.py retire D-03 --why "…"
python 脚本\workbench.py pitfall "…"
python 脚本\workbench.py blocker add "…"
python 脚本\workbench.py next set "…"
python 脚本\workbench.py render          # 渲染 md + 刷新启动包
python 脚本\workbench.py compare         # 双写期看差异
python 脚本\wb_archive.py                # 把 retired 归档到 L3
python 脚本\wb_query.py D-03             # 查已作废条目
```

## 已作废的条目去哪了

`记忆\L3\归档\任务看板-已作废.md`（带 sha 校验）。json 里仍保留，但不进 md、不进注入。

## 2026-10-28 新增三条（清理机制）

1. **已定最多 15 条 / 900 汉字**（首期；两周后收到 12/800）。
   超了 `render` 会拒绝收尾（退出码 1），先跑 `workbench.py prune` 看该退哪些。
2. **写之前先回答一句**：删了它，下一个人会不会做错事？
   答案是「不会」，就只写进文件，**不进任务看板**。
3. **一次性事实必须带 `expires`**：
   发布类＝数据回填后 +3 天；交付类＝验收后 +7 天。
   `workbench.py decide "…" --pointer … --expires 2026-11-02`

**keep**：确实不能退的，`workbench.py keep D-xx --why "…"`，30 天内不再进候选；
同一句被 keep 超过 3 次会提醒你——要么它真重要（写进文档），要么该退了。
