# L2 规范（记忆层）

> **一句话**：L2 是**被提炼过、会被注入**的经历——常驻层（她站的时间点）+ 关键词层（按主题唤起）+ 待确认区（还没签字的）。
> **真源**：`记忆/memory.db`（SQLite）；`记忆/记忆.md`、`记忆/场景投影.md` 是**自动导出的视图**（手改无效）。
> 生效版本：v0.5.6。与 `规格/工作流程-v0.5.6.md` 冲突时以规格为准；本文件把散在 §2/§4/§6/§12 与 `记忆.md` 前言的 L2 规则收拢成一份可执行规范。

---

## 1. 它是什么、不是什么

| 是 | 不是 |
|---|---|
| 她**经历过什么**（叙事式） | 不是"她学会怎么做"——那是 L1 |
| **已被提炼、会被注入**的内容 | 不是原始流水——那是 L3（永不注入） |
| 有常驻/关键词两层、有场景标签 | 不是工作现场（"我们刚在改 SKILL"）——那是任务看板 |
| 写入要过待确认区、要你签字 | 不是自动生效的 |

**三条边界**：

1. **vs L3**：L3 是原文，L2 是提炼。**L3 → L2 只有一条路**：提炼成一条 → 待确认区 → 你签字。
2. **vs L1**：L2 里的**处方内容一律清出来归 L1**（"以后要避免 X"不是记忆，是规则）。
3. **vs 任务看板**：任务看板是几小时内的现场；L2 是过了闸、值得长期留着的事。

## 2. 条目类型与字段

### 2.1 两层与类型

| 层 | 类型（`category`） | 条数 | 注入 |
|---|---|---|---|
| **常驻层** | 当前状态 / 成长记录 / 与 Maker 的关系 / 我的来处 | 各 1 条 | **每次无条件** |
| **关键词层** | 身份与来历 / 梗库 / 玩梗判例 / TTS 实测 / 账号回填 / **讲过的主题** | 不限（同类 >12 条要合并） | 主题命中才注入 |
| **待确认区** | 任意（落区时 `启用=0`、`待确认=1`） | ≤5 条 | **不注入** |

### 2.1.1 原话区不参与整理（2026-10-29 · {角色名}定）

> 判据是内容写在哪，不是模型觉得它重不重要。

| 区 | 包含 | 规则 |
|---|---|---|
| **原话区** | `成长记录`（她的原话）、触动条目、handoff 的 `原话：`、`日常原话.md` | **只增、不改、不压、不摘要**；不参与任何整理、合并、提炼 |
| **事实区** | 当前状态、身份与来历、梗库、TTS 实测、账号回填等 | 可压、可合并、可摘要 |

三条推论（同 L3 §2.1）：

1. **原话不该被判断**——分区由字段/文件决定，不由模型判断；
2. 压缩版只走**检索路径**，不进正文；
3. 卡片：**规则可压，样本不可压**。


### 2.2 字段

| 字段 | 必填 | 语义 | 谁写 |
|---|---|---|---|
| `num` | ✅ | 条目号（三位以内），**不复用** | 脚本 |
| `layer` | ✅ | 常驻层 / 关键词层 / 主题索引 / 待确认（脚本按 `constant`/`pending` 推导） | 脚本 |
| `category` | ✅ | 见 2.1 的类型名 | 写入时 |
| `title` | ✅ | 标题，**全局唯一**（重复即拒收） | 写入时 |
| `keywords` | 关键词层必填 | `_or_` 分隔；常驻层留空 | 写入时 |
| `insert_order` | ✅ | 注入排序（常驻 1–9，关键词 10+，待确认 1000+） | 脚本 |
| `enabled` | ✅ | 1 = 生效；0 = 不注入 | **只有 `approve` 能置 1** |
| `pending` | ✅ | 1 = 在待确认区 | `add` 置 1；`approve`/`reject` 置 0 |
| `constant` | ✅ | 1 = 常驻层 | 写入时（`--constant`） |
| `scene` | ✅ | `通用 / 日常 / 工作`（缺省=通用） | 写入时 |
| `source` | ✅ | `reflection`（写稿沉淀）/ `maker`（你手给）/ `account`（账号数据回填）/ `import`（迁移） | 写入时 |
| `date` | ✅ | 写入日期 `YYYY-MM-DD` | 脚本默认今天 |
| `status` | ✅ | `active` / `superseded`（被新版取代）/ `rejected`（拒收） | `approve`/`reject`/合并 |
| `last_cited_ep` | — | **最近一次被注入使用的期号**（三位） | 写稿流程落盘时 `cite` |
| `raw` | ✅ | 条目的原文块（导出的就是它） | 脚本 |

> **v0.5.6 前的遗留问题**：`source / date / last_cited_ep / status` 一直没人填。本规范生效后，**新写入必须填**；存量 12 条由脚本补默认（`source=import`, `date=2026-10-26`, `status=active`）。

## 3. 上限与滑窗

> 数字全部标注"**拍的**"，首轮真实运行后校准。

| 对象 | 上限 | 超了怎么办 |
|---|---|---|
| 常驻层总数 | **4 条**（当前状态/成长记录/关系/来处各 1） | 合并进已有条，不许新增第 5 条 |
| 常驻层体积 | ≤**900 汉字**（约 1400 token） | 压缩；成长记录取最近 8 周 |
| 单条关键词层 | ≤**600 汉字** | 拆分或压缩 |
| 同类关键词条 | >**12 条**必须合并成一条"索引式"条目 | 合并 |
| 待确认区 | ≤**5 条** | 满了就**停止沉淀**（`add` 报错），先清 |
| 待确认超时 | >**14 天**未处理 → 报旗（不自动清理） | 你裁决 |
| 一次检索注入量 | 常驻 + 命中 ≤**2000 token** | 命中太多时按 `insert_order` 截断，并在输出里注明"截断" |

**注入滑窗**：
- 常驻层：**全量**（4 条）；
- 成长记录：取**最近 8 周**或最近 **5 条**（取先到者），旧的留库不注入；
- 主题索引（第 11 条〈讲过的主题〉）：**只取当前主题命中的那 1–2 行**，不整表注入。

## 4. 待确认区生命周期

```
add（启用=0, 待确认=1）
   ↓
你看（memory_db.py list --scene 工作 / source --id）
   ↓
┌──────────────┬──────────────────┐
approve         reject
启用=1, 待确认=0  status=rejected, 待确认=0
status=active     （保留条目，可查，不注入）
   ↓
导出视图 → 下次注入生效
```

**四条规则**：

1. **超时默认维持现状**：没签字 = 不生效，不会"过期自动通过"。
2. **拒绝要写理由**（`--reason`），理由进 `raw` 末尾，便于以后回看。
3. **签字必须留痕**：`l1_changelog` 之外，L2 也要有一份 `l2_changelog`（时间/动作/条号/理由）。
4. **拒绝不等于删除**：条目留着（`status=rejected`），以后可以复用或改成新条。

> **当前缺口（本规范要求必须补）**：`memory_db.py` 没有 `approve` / `reject` / `cite` 三个动作。规范生效后补上，否则"签字"只能手改库，无法留痕。

## 5. 关键词与场景检索

### 5.1 关键词匹配规则

- 分隔符：`_or_`（导出时保留，解析时去掉）；等价于"或"。
- **子串匹配**，**忽略大小写**（中文不受影响，英文缩写受益）。
- 单关键词最短 2 字；1 字关键词不许入库（命中率太高）。
- 同义词靠**在条目里多写几个关键词**解决，不建同义词表（简单优先）。
- 命中判定：当前主题/人物/梗包含任一关键词 → 命中。

### 5.2 场景过滤（双投影）

| 当前投影 | 注入哪些场景 |
|---|---|
| 日常 | `通用` + `日常` |
| 工作-口播 | `通用` + `工作` |

> **当前状态（2026-10-27 更正）**：`memory_lookup.py` **已经有 `--scene`**，默认 `工作`。原「没有 `--scene`、实际没隔离」这句已过期，删掉。
>
> **两条新增（同日，按执行报告 B/C）：**
> - `scene` 不许再靠缺省。新增条目时必须显式指定：纯工作的事写 `工作`，聊天里会提到的事才写 `通用`。
>   这次实测：`TTS 读法实测表`、`账号数据回填` 两条纯工作的，因为缺省成了 `通用`，天天进日常包。已改。
> - **常驻层只写跨场景成立的事。** 进度（待发布、播放数、这一期到哪一步）不进常驻层，进任务看板或 T1。
>   这次实测：常驻第 1 条写着「第 1 支已交付，待发布」，第一期早发了，日常包里天天是过期状态。已改。

### 5.3 检索顺序（写稿时的取数）

1. **常驻层**（无条件，永远第一）；
2. **场景层**（按 `--scene` 过滤）；
3. **关键词命中**（按 `insert_order` 排序）；
4. 超量截断（见 §3），并在输出头注明 `[已截断]`。

## 6. 冲突与合并

| 情形 | 处理 |
|---|---|
| 同 `title` 再写入 | **拒收**（脚本直接拦） |
| 两条内容矛盾（例：一条说"第 1 期已交付"，一条说"第 1 期未发布"） | 新条进待确认区，`raw` 末尾自动加 `冲突：与 #NN 矛盾`；你裁决保留哪条 |
| 一条过时、一条更新 | 旧条 `status=superseded`（保留可查、不注入），新条生效 |
| 同类 >12 条 | 合并成一条"索引式"条目，旧条 `superseded` |
| 常驻层与事实不符（如"当前状态"过期） | 必读项：**每期交付后必须更新**（见 `工作/SKILL.md` 第 8 步） |

**原则：只加不删，过时用 `superseded` 标，不用删除。** L2 不像 L3 那样绝对只追加，但也**不物理删除**——否则"她以前以为的是什么"就查不到了。

## 7. 主题索引维护（第 11 条）

- **触发**：每次写稿选了一个**她以前讲过**的主题（扩散模型、AI 幻觉、tokenizer…）。
- **动作**：在〈讲过的主题〉表里**追加一行**（期号 / 主题 / 讲过什么 / 在这个点上讲错过什么 / 下次怎么讲）。
- **同一主题再次讲错**：追加新行，**不覆盖旧行**。
- **不命中就不注入**：条目本身是关键词层，关键词=主题词；当前主题没命中就不出现。
- **条目号**：固定为第 11 条（模板），具体主题的行在条目**正文表格**里，不各占一个条号。

## 8. 权限与校验

| 角色 | 能做什么 |
|---|---|
| **agent** | 只能 `add`（进待确认区）；不能 `approve`、不能改 `enabled`、不能改已生效条目的正文 |
| **maker** | `approve` / `reject` / 直接改条目（改后要留痕） |
| **脚本** | 校验（字段完整、标题唯一、条数上限、导出与库一致）、生成视图、报旗 |

**三条机器硬线（规范生效后必须满足）**：

1. **`import` 不许丢元字段**：迁移/回灌时按 `num` upsert，保留 `source/date/last_cited_ep/status`；旧实现"清表重建"必须改掉。
2. **视图与库一致**：`export` 后条数必须相等；`export` 前若检测到 md 被手改，**拒绝覆盖并报错**（提示"改库重导出"）。
3. **待确认区 ≤5 条**：`add` 时检查，超了直接报错。

## 9. 与其它层的接口

| 方向 | 规则 |
|---|---|
| L3 → L2 | 只有一条路：提炼 + 待确认 + 签字（见 §4） |
| L2 → L1 | 常驻层里的**处方内容**必须清出来归 L1（§1 边界 2） |
| L2 → L0 | 不进 L0；L0 只由 L1 毕业或你直改 |
| L2 → 移植包 | 只带**常驻层摘要**，不搬全部关键词层 |

## 附：日常原话（7 天缓冲，2026-10-28 加）

| 项 | 定 |
|---|---|
| 位置 | `记忆/日常原话.md`（L2 层根下，**不在 L3**） |
| 内容 | 上一次聊天说过的 ≤3 句**原话**：`- 他：「…」` |
| 写入 | 完整模式收尾时 `note_daily`；投影模式拒绝 |
| 上限 | ≤3 句/次、≤40 汉字/句；含播放/期数/待办直接拒 |
| 注入 | 日常包「## 上一次聊天，说过的三句」；无记录整块不出现 |
| **保留期** | **7 天**；超期整节默认丢弃，只写 `日常原话.json` 记账（哪天/几句/sha256）；`--archive` 才移进 `日常原话-归档.md` |

**为什么放 L2 不在 L3**：它是"上一轮说了什么"的临时缓冲，用完就该没；
放进 L3（永久只追加）会让"永久记忆"混进一次性内容，也会把 7 天清理变成违例。

## 附二：卡化与签发对 L2 的影响（2026-10-29 加）

L2 的**内容规则没变**，变的是"谁能写、以什么形态进包"。

### 1. 写入权：判据是签发，不是模式

| 旧 | 新 |
|---|---|
| 完整模式能写、投影只读 | **会话级签发**：有票能写、没票只读（与客户端无关） |

- 写 L2 的工具：`stage_memory`（提案进待确认区）、`note_add`、`note_daily`；
- 需要的签发项：`write:memory`；
- 票的来源：`脚本/grant.py sign --tools write:memory`（B 模式 4h／A 模式单次票）；
- 审计：每次尝试与结果都落 `记忆/L3/_签发.jsonl`（宿主直写，不依赖票）。

### 2. 记忆卡（`kind: memory`）不是 L2 的替代

| 概念 | 存放 | 作用 |
|---|---|---|
| **L2 条目** | `memory.db` | 长期记忆，按关键词/场景过滤后注入 |
| **记忆卡** | `skills/*.md`（`kind: memory`） | **一次任务要用的素材**（如"本期素材"），带 `provenance` 与 `stale_after` |

规则：
- 记忆卡**只放"这次要用的"**，长期知识仍进 L2；
- 记忆卡有**独立额度**（`material_max_han = 1500`），不占技能卡额度；
- 卡里的事实必须带来源（`provenance.source` + `date`），过期打「旧卡」章。

### 3. 任务卡与 L2 的分界

| 放哪 | 放什么 |
|---|---|
| 任务卡（`kind: task`） | 一个交付物的**步骤 + 每步判据**（稳定，可分享） |
| 任务实例账（`记忆/L3/任务/<id>.jsonl`） | 当前第几步、何时过的（天天变） |
| L2 | "发生过什么 / 她学到什么事实"（长期） |

一句话：**卡是流程，账是进度，L2 是记忆。三者不许互相顶替。**
