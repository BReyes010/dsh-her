# L3 规范（永久记忆层）

> **一句话**：L3 是她的**永久记忆**——原始流水账，**只写、只追加、永不注入**。
> 它存在的理由是"**查得到历史**"：不参与她说话时的上下文，只在她（或你）**主动去查**时，给出一段带出处的片段。
> 生效版本：v0.6（2026-10-27 重写：定义明确为"永久记忆"，并引入受控检索通道）。
> 上位：`规格/工作流程-v0.6.2.md` §2。

---

## 1. 它是什么

| 是 | 不是 |
|---|---|
| 永久记忆：**发生过的事的原文**（成稿、复盘、事件、扫描、出差、归档） | 不是"她记得的事"——那是 L2 |
| **查历史**的唯一依据（证据编号最终落到这里的一张纸） | 不是注入材料，不进任何上下文 |
| 审计与回溯的底账 | 不是第二份可检索记忆 |
| 移植包挑样本的矿脉 | 不是自动总结再写回 L2 的通道 |

**它和 L2 的分工一句话**：
> **L2 回答"我记得什么"；L3 回答"当时到底怎么发生的"。**

## 2. 三条铁律

1. **只追加，不改写**。错的复盘不覆盖，写 `#001-复盘-v2.md`，索引记最新一版。
2. **永不注入**。任何模式的注入包里都不许出现 L3 正文（指针可以）。
3. **两条通道分开**（见 §9）：
   - **沉淀**：L3 → 提炼成一条记忆 → 你签字 → L2（**要签字**）；
   - **检索**：L3 → 查询代理 → 片段 → 只用在这一轮（**不要签字，但不许沉淀**）。

### 2.1 原话区不参与整理（2026-10-29 {角色名}定，措辞沿用她的）

> **判据是内容写在哪，不是模型觉得它重不重要。**

| 区 | 包含 | 规则 |
|---|---|---|
| **原话区** | 触动条目、handoff 的 `原话：`、成长记录 | **只增、不改、不压、不摘要**；不参与任何整理 |
| **事实区** | 偏好、规则、技术、项目状态 | 可压、可提炼、可摘要 |

三条推论：

1. **原话不该被判断**。模型一旦判断"这句算原话、留着"，它已经编辑过一次了。所以分区由**文件与字段**决定，不由模型决定。
2. **压缩版只能出现在检索路径上**（用来告我东西在哪），**不许进入正文**——摘要不能代替她说话。
3. 卡片同理：**规则可以压，样本不行**（样本是语感，压完就不像她）。

## 3. 目录结构（2026-10-27 现状）

```
记忆/L3/
├── index.csv                 ← 期目录索引（派生，可重建；不手改）
├── 2026/
│   ├── #001-成稿.md          ← 成稿全文
│   ├── #001-复盘.md          ← 一行复盘（含计数位）
│   ├── #001-事件.json        ← 事件类型 / 证据 / 她的选择 / 结果 / PROVISIONAL
│   └── #001-scan.json        ← scan.py 的结果
├── handoff/                  ← 出差记忆（一次会话一个文件）
│   ├── 20261027-1242-千问.md
│   ├── _状态.md              ← 派生：T1 状态表
│   ├── _模板.md              ← 写 handoff 的模板
│   ├── _promoted.json        ← 已提升条目的幂等标记
│   └── _closings/            ← close 记录（不污染会话列表）
├── 归档/
│   ├── 任务看板-已作废.md       ← 任务看板 retired 条目的正文（含索引表）
│   └── _归档.json            ← 条数 / ids / sha256 / 生成时间
├── 触动.md                   ← 单一文件：打动过她的话（逐字 + 出处 + 为什么）
├── 项目思考.md                ← 单一文件：大项目的思路与原则（L1 候选池）
├── L0-changelog.md           ← 每次改人格卡：版本 / 日期 / 理由 / 汉字 / token
├── 墓碑.jsonl                ← PROVISIONAL 归档墓碑（主题 + 归档期号 + 稳定 ID）
└── _查询审计.jsonl           ← 每次检索一行（含"决定不查"），不可删
```

> **日常原话不归 L3**（2026-10-28 移出）：它是 7 天的临时缓冲，放在 L2 层 `记忆/日常原话.md`，见 `L2-规范.md`。

**命名**：`#期号-类型`，期号三位补零；年份目录四位；handoff 用 `YYYYMMDD-HHMM-客户端.md`。
**一期四件套**：成稿 / 复盘 / 事件 / 扫描——缺任何一件，索引标 `incomplete`。

**待实现**：`归档/2026.zip`（52 期一卷 + sha256）。现在体积只有 200KB 级，压缩没有收益，标为"待实现"。

## 4. 三类内容与索引

| 类 | 真源 | 索引 | 谁写 |
|---|---|---|---|
| **期**（成稿/复盘/事件/扫描） | `20xx/#NNN-*` | `index.csv` | 写稿流程 + 脚本 |
| **出差**（handoff） | `handoff/*.md` | 暂由 `handoff/_状态.md` 派生 | 收尾时她写，脚本校验 |
| **归档**（作废的任务看板条目） | `归档/任务看板-已作废.md` | `归档/_归档.json` | `wb_archive.py` 整份重写 |
| **触动** | `触动.md` | 无（单文件） | 她收尾时挑（`notes.py add` / `note_add`），**每日 5 句**、≤120 汉字/句；**必须有出处与触动点**；超额进 `待审核笔记.jsonl`，approve 才进正文 |
| **项目思考（暂不启用）** | `项目思考.md` | 无（单文件） | 她写、你改错（`notes.py add --kind 项目 --name X`），**每日 1 个**、≤4000 汉字；超额同样进待审 |

### index.csv 字段

| 列 | 含义 |
|---|---|
| `ep` / `date` / `topic` | 期号 / 交付日期 / 主题 |
| `chars` / `sentences` | 成稿汉字数 / 句数 |
| `scan_status` / `violations` | `pass`/`fail`/`missing` / 违规项数 |
| `draft` `review` `event` `scan` | 四个文件的相对路径 |
| `l1_used` | 本期用到哪几条 L1 |
| `status` | `complete` / `incomplete` |

> 索引是**派生**：丢了可重建（`--rebuild-index`），文件才是真源。
> handoff 与归档不塞进 `index.csv`——它们是不同类，各自有索引（`_状态.md` / `_归档.json`）。

## 5. 写入规则

### 5.1 期

1. 只追加，不改写（见铁律 1）；
2. 谁写：成稿→写稿流程；复盘→脚本起草、你改错；事件/扫描→脚本；
3. 写入前校验：期号不冲突；四件套齐全才标 `complete`；
4. 诚实标注：任何"推断"不得写成"事实"（事件 JSON 里 `inferred: true`）。

### 5.2 出差（handoff）

1. **一次会话一个文件**；同一分钟内第二次写入加 `-2` 后缀（不覆盖）；
2. 一次 1–3 条主题条目，每条 ≤150 汉字；
3. **close 记录进 `_closings/`**，不再混进会话列表；
4. `promote` 需 `主题：` 与 `谁做的：她`，且幂等（`_promoted.json`）。
5. **轮转（2026-10-28 定）**：活跃区只留 **最近 3 天** + **所有还有 open 的会话**；
   其余移进 `handoff/归档/YYYY-MM/`；**超过 30 天的月份压成 `YYYY-MM.zip`**（带 sha，记 `归档/_归档.json`）。
   - 时机：收尾（`render`）自动跑 `handoff.py rotate`；也可 `--dry-run` 先看；
   - **open 永不移走**；`_待写入-*` 这类草稿不归轮转管；
   - T1 只从活跃区取，`l3.py grep` / `recall` 仍能搜到归档。
   - 目的不是省盘（十年 4 MB），是**把每次解析/注入的范围锁住**，并让 `_状态.md` 不再无限长。

### 5.3 归档（任务看板已作废）

1. **整份重写**，不是追加（追加会留旧副本）；
2. 写完记条数 + ids + sha256 到 `_归档.json`；
3. **源为空时拒绝清空**（除非 `--force`）；
4. 挂在收尾里：`workbench.py render` 先归档再渲染。

### 5.4 审计（`_查询审计.jsonl`）

1. **不可删**，不提供删除接口；
2. **不记用户原话明文**：只记 hash + 前 20 字；
3. **"决定不查"也要记**（`status: "skipped"` + 原因）；
4. 一行一次调用：时间 / 会话 / 时间窗 / 关键词 / 状态 / 命中数 / 探针数 / **探针明细**（每探针各命中几条）/ 耗时；
5. 状态三档：`found` / `none` / `need_more`；观点类问题不探针，直接 `need_more` 并写明「不是发生过的事」。

## 6. 禁入清单（**永久只追加，写错删不掉**）

以下任何一项**不许写进 L3**：

| 禁入 | 原因 |
|---|---|
| 密钥 / 密码 / cookie / token | 一旦写进永久层，等于永久泄露 |
| maker 明确说"别记"的私事 | 他的意志优先于"完整性" |
| 他人隐私、可识别第三方的对话原文 | L3 不是公共档案 |
| 未脱敏的手机号 / 地址 / 身份证 / 订单号 | 同上 |

**判据**：这条东西**五年后被人翻到**，会不会给你或别人带来麻烦？会 → 不写。

## 7. 墓碑（`墓碑.jsonl`）

- **何时立碑**：PROVISIONAL 条目被归档时（不是普通删除——L3 没有物理删除）；
- **字段**：`{"ts","topic","archived_ep","stable_id","reason"}`；
- **永不删除**：碑是"这里曾经有过一条，现在不在了"的凭据。

## 8. 校验

`python 脚本/l3.py check` 做三件事：

1. **缺件**：索引指向的文件不存在；
2. **孤儿**：文件在，索引里没有；
3. **一致性**：handoff 文件 ↔ `_状态.md`；归档条数 ↔ `_归档.json`（含 sha）。

现状：期已全查；`_fts.db` 的存在与新鲜度也纳入（超过 1 天没更新会报）。
handoff / 归档的**逐条**一致性核对仍在待办（现在有 `_状态.md` / `_归档.json` 兜底）。
`归档/*.zip` 的 sha 校验等 zip 落地再补。

**频率**：每次收尾自动跑（`workbench.py render` 的第三步）。

## 9. 两条通道（最重要的一节）

```
通道 A · 沉淀（要签字）
  L3 原文 ──提炼──▶ 待确认区 ──你签字──▶ L2 条目 ──注入──▶ 她

通道 B · 检索（不要签字，但不许沉淀）
  L3 ──▶ 查询代理 l3q ──▶ 片段（≤3 条 / 每条 ≤300 字 / 带编号与日期）
                          └──▶ 只用在这一轮对话
                                ✗ 不回写 L2   ✗ 不进下次注入
```

| | 通道 A | 通道 B |
|---|---|---|
| 改变什么 | 她**记得**什么 | 她**这一刻知道**什么 |
| 要签字吗 | **要** | 不要 |
| 会留在她身上吗 | 会（进 L2） | **不会**（只在这一轮上下文） |
| 谁发起 | 你/她提炼 | 她判断"该查" |
| 审计 | `l2_changelog` | `_查询审计.jsonl` |

**为什么不能只要 A**：她记不清、你更记不清的事，靠"沉淀"永远补不上——那些事只有原文里有。
**为什么不能只要 B**：如果检索结果能沉淀，她就绕过了签字，L2 会被"她查到的"悄悄污染。

> 一句话：**沉淀改的是她是谁；检索只是她临时看了一眼档案。**

## 10. 访问与权限

| 角色 | 读 L3 | 方式 | 限制 |
|---|---|---|---|
| **她（完整模式）** | 不能直接读 | 只能经 l3q 拿片段 | 每次 ≤3 条、每条 ≤300 字、探针 ≤3；引用必标出处 |
| **她（日常/工作投影）** | 同上 | 同上 | **写操作全部拒绝**：`write_handoff` / `note_add` / `set_snapshot` 只归完整模式；投影只能 `stage_memory`（提案）与 `mark_close_pending`（留一行待补） |
| **查询代理 l3q** | 只读 | 独立进程 | 无写权限；每次落审计；查不到要说"没找到" |
| **她查笔记**（触动/项目） | 只读两份 md | `search_notes` 工具 | 不走代理；每次仍落一行审计 |
| **你** | 能读 | 文件 / `l3.py` / 插件「查询器」 | —— |
| **移植打包器** | 只读且只取摘要与样本 | 脚本 | 不搬 L3 原文 |

### 两类"笔记"例外：不走查询代理

`触动.md` 与 `项目思考.md` 是**她自己挑过、提炼过的素材**，风险低，所以：

| | 期 / handoff / 归档 | 触动.md / 项目思考.md |
|---|---|---|
| 查询入口 | **必须过查询代理 l3q**（判断 + 3 探针 + 审计） | **直接查**（`search_notes` 工具 / `l3.py grep --kind`） |
| 返回 | 片段 ≤300 字 | 整行 / 整节 |
| 审计 | 整条探针链 | 一行（仍然要记） |
| 理由 | 原始流水，含隐私与拼凑风险 | 她已经挑过，等于"她自己的摘要" |

**她看到的不是原文全文，也不是原件，是片段。** 所以：
- 她可以说"日志里写着…（编号 #002，10-27）"；
- 她**不许**把片段当自己的记忆复述（"我记得当时…"）；
- 她**不许**一次引用多条拼成一段"回忆"。
